⚡ Quickstart

  1. Copy and configure environment
    cp .env.example .env
# Open .env and set DATABASE_URL, REDIS_URL, SECRET_KEY
  2. Create virtual environment & install dependencies 
    python -m venv .venv
# Windows
.venv\Scripts\activate
# Linux / Mac
source .venv/bin/activate

pip install -r requirements.txt
  3. Run database migrations 
    alembic upgrade head
  4. Start everything with one command 
    # Windows (dev)
.\scripts\dev.ps1

# Linux (production)
bash scripts/prod.sh
    ℹ️
    On Windows, the dev script opens Windows Terminal tabs (or separate PowerShell windows if WT is not installed). It also auto-runs migrations and checks Redis for you.

🧩 Services Overview

FastAPI
All HTTP endpoints — auth, CRUD, WebSocket. Runs on port 8000.
Redis
Token blacklist · RBAC permission cache (TTL 300s) · Rate limiting · Celery broker
Celery Default
Welcome emails · Blotter PDF generation · Cleanup old logs (weekly)
Celery Priority
Emergency notifications — separate queue so alerts are never delayed by normal jobs
Celery Beat
Scheduled jobs: delete system_logs rows older than 90 days — every Sunday 02:00 UTC
PostgreSQL
Primary database. Async via psycopg3. Pool: 10 base + 20 overflow, recycles every 30 min.

💻 Development (Windows)

One command to rule them all

# From project root in PowerShell
.\scripts\dev.ps1

This script: checks .env → checks venv → pings Redis → runs migrations → opens all 4 service tabs.

Stop all services

.\scripts\stop.ps1

Kills uvicorn, all celery processes, and any Celery subprocesses. Safe to run at any time.

ℹ️
Services started by dev.ps1 run as independent background processes — closing the launcher window does not stop them. Always use stop.ps1 or press Ctrl+C inside each tab.

Or run services manually (4 terminals)

# Terminal 1 — FastAPI
uvicorn app.main:app --reload --port 8000

# Terminal 2 — Celery default worker
celery -A app.workers.celery_app worker -Q default --loglevel=info --pool=solo

# Terminal 3 — Celery priority worker (emergencies)
celery -A app.workers.celery_app worker -Q priority --loglevel=info --pool=solo

# Terminal 4 — Celery Beat (scheduler)
celery -A app.workers.celery_app beat --loglevel=info
⚠️
Windows requirement: Always add --pool=solo to Celery workers on Windows. The default prefork pool is not supported on Windows.

🚀 Production (Linux / EC2)

One command

bash scripts/prod.sh

If supervisord is installed it will use it (recommended). Otherwise it falls back to launching processes directly with graceful shutdown on SIGTERM.

Install supervisor (recommended)

pip install supervisor
# Then just run:
supervisord -c scripts/supervisord.conf

# Control running services:
supervisorctl -c scripts/supervisord.conf status
supervisorctl -c scripts/supervisord.conf restart bmis:api
supervisorctl -c scripts/supervisord.conf restart bmis:all

Or run manually (Linux)

# FastAPI — 4 Gunicorn workers
gunicorn app.main:app \
  -k uvicorn.workers.UvicornWorker \
  --workers 4 --bind 0.0.0.0:8000 --timeout 60

# Celery default worker
celery -A app.workers.celery_app worker -Q default --loglevel=warning --concurrency=4

# Celery priority worker
celery -A app.workers.celery_app worker -Q priority --loglevel=warning --concurrency=2

# Celery Beat
celery -A app.workers.celery_app beat --loglevel=warning
💡
Use systemd unit files or supervisord in production so all processes auto-restart on crash and start on server boot.

🔐 RBAC — Roles & Permissions

The seed script runs once on first deploy to bootstrap the system: it creates the 4 built-in roles, default permissions, and the initial super-admin account. All ongoing role and permission management is done via the API or UI — no need to touch the seed script again.

How it works

StepWhat happens
1. Request arrivesJWT is validated, user_id extracted from token.
2. Permission lookupUser's roles are fetched, all permissions for those roles are combined. Result is cached in Redis for 300s.
3. Permission checkThe required permission for the endpoint (e.g. blotter.create) is checked against the user's permission set.
4. Allow / DenyIf the user has the permission → request proceeds. If not → 403 Forbidden.

Default roles

RoleWhat they can do
super_adminAll permissions — full system access including RBAC management.
barangay_adminAll module permissions except rbac.manage.
staffRead/manage operational modules (blotter, certs, permits, complaints, emergency, chat). No user or RBAC management.
residentOwn profile and chat only.

Default permission codes

CodeWhat it guards
users.read / users.manageGET / POST, PATCH, DELETE on users
profiles.read / profiles.manageResident profile endpoints
announcements.manageCreate, update, delete announcements
blotter.read / blotter.manageBlotter report endpoints
certificates.read / certificates.manageCertificate request endpoints
business_permits.read / business_permits.manageBusiness permit endpoints
complaints.read / complaints.manageComplaint endpoints
emergency.read / emergency.manageEmergency report and alert endpoints
chat.read / chat.manageChat history and send message
rbac.read / rbac.manageRead/manage roles, permissions, assignments
system_logs.readGET /system-logs/ admin endpoint

How to add a new permission

New permissions are created at runtime via the API — no seed script needed. Requires rbac.manage permission.

# Step 1 — Create the permission via API
POST /rbac/permissions
{
  "code": "reports.create",
  "module": "reports",
  "action": "create",
  "name": "Create reports"
}

# Step 2 — Assign it to a role
POST /rbac/roles/{role_id}/permissions
{
  "permission_ids": ["<permission_uuid>"]
}

# Get all permission UUIDs
GET /rbac/permissions

How to add a new role

Custom roles are created at runtime via the API — no seed script needed. Only the 4 built-in system roles (super_admin, barangay_admin, staff, resident) come from the seed. System roles are protected and cannot be modified or deleted via the API.

# Step 1 — Create the role via API (requires rbac.manage permission)
POST /rbac/roles
{
  "code": "auditor",
  "name": "Auditor",
  "description": "Read-only access to operational modules"
}

# Step 2 — Assign permissions to the role
POST /rbac/roles/{role_id}/permissions
{
  "permission_ids": ["<uuid>", "<uuid>"]
}

# Step 3 — Assign the role to a user
POST /rbac/users/{user_id}/roles
{
  "role_id": "<uuid>"
}
ℹ️
You can get all available permission UUIDs from GET /rbac/permissions (requires rbac.read). The Swagger UI at /docs is the easiest way to do this interactively.

How to protect a new endpoint

# GET endpoint
@router.get("/reports/", dependencies=[Depends(requires_permission("reports.read"))])
async def list_reports(...):
    ...

# POST endpoint
@router.post("/reports/", dependencies=[Depends(requires_permission("reports.create"))])
async def create_report(...):
    ...

# PATCH endpoint
@router.patch("/reports/{id}", dependencies=[Depends(requires_permission("reports.manage"))])
async def update_report(...):
    ...

# DELETE endpoint
@router.delete("/reports/{id}", dependencies=[Depends(requires_permission("reports.manage"))])
async def delete_report(...):
    ...

Workflow summary

  1. First deploy only — run python -m scripts.seed once to create system roles, default permissions, and the initial super-admin.
  2. Add a new permission — POST /rbac/permissions via the API or Swagger UI.
  3. Add a new role — POST /rbac/roles via the API or Swagger UI.
  4. Assign permissions to a role — POST /rbac/roles/{id}/permissions.
  5. Protect a new endpoint — add dependencies=[Depends(requires_permission("your.permission"))] to the route decorator.
  6. Clear Redis cache (dev only) — run redis-cli FLUSHDB to see permission changes immediately without waiting 300s.
💡
The seed script is idempotent — always safe to re-run. It checks for existing records before inserting so you will never get duplicates.
⚠️
After re-seeding, Redis caches old permissions for up to 300 seconds. In development, flush with redis-cli FLUSHDB to see changes immediately. In production, the cache will expire naturally.

📋 Logging & Observability

stdout
All logs appear in the terminal. Format: timestamp | LEVEL | logger | message
system_logs table
Every log at or above LOG_LEVEL_DB is written async to the DB. Query at GET /system-logs/ (requires system_logs.read permission).
logs/ directory
Supervisor writes per-service log files here: api.log, celery_default.log, celery_priority.log, celery_beat.log

Query system logs via API

# List recent errors
GET /system-logs/?level=ERROR&limit=50

# All actions by a specific user
GET /system-logs/?user_id=<uuid>&limit=100

# Filter by action prefix + date range
GET /system-logs/?action=EMERGENCY&from_dt=2026-05-01T00:00:00Z

# Count for pagination
GET /system-logs/count?level=WARNING
💡
Logs older than 90 days are automatically deleted by the cleanup_old_logs Celery Beat task every Sunday at 02:00 UTC. You can change the retention period by editing app/workers/celery_app.py.

🛠️ Stack Used

Every technology in this project, what it does, and why it was chosen.

FastAPI

RoleHTTP API framework — handles all routes, middleware, request validation, and WebSocket connections.
WhyAsync-first, Pydantic v2 integration for zero-boilerplate validation, automatic OpenAPI/Swagger docs, and one of the fastest Python frameworks available.
Version0.136
Key filesapp/main.py · app/api/routes/ · app/modules/*/router.py

Pydantic v2

RoleData validation and serialization for all request bodies, response models, and settings.
Whyv2 is 5-50x faster than v1 (Rust core). ConfigDict and model_validator give clean, type-safe schemas with minimal boilerplate.
Key filesapp/modules/*/schema.py · app/core/config.py (uses BaseSettings)

SQLAlchemy 2 (async)

RoleORM and query builder for all database interactions. All queries run async — they never block the event loop.
WhyIndustry-standard ORM with full async support via AsyncSession. Declarative models, relationship loading, and migration support via Alembic.
Pool config10 base connections · 20 overflow · recycles every 30 min · LIFO order · rollback on return
Key filesapp/db/session.py · app/modules/*/model.py

psycopg3

RolePostgreSQL driver — the low-level connector between SQLAlchemy and the database.
WhyNative async support (unlike psycopg2 which requires a thread pool workaround). Better performance and binary protocol support.
Key filesapp/db/session.py — connection string uses postgresql+psycopg://

PostgreSQL (AWS RDS)

RolePrimary relational database — stores all application data: users, profiles, blotters, certificates, complaints, permits, chat, emergency reports, and system logs.
WhyACID-compliant, excellent support for UUID primary keys, JSONB, full-text search, and row-level security. AWS RDS handles backups, failover, and patching.
Key configDATABASE_URL in .env

Alembic

RoleDatabase migration tool — tracks schema changes and applies them in order without touching existing data.
WhyOfficial SQLAlchemy migration companion. Version-controlled migrations mean the DB schema is always reproducible from scratch.
Commandsalembic upgrade head — apply all pending migrations
alembic revision --autogenerate -m "msg" — generate a new migration
Key filesalembic/ · alembic/versions/ · alembic/env.py

Redis 7

RoleMulti-purpose in-memory store used for 4 separate concerns:
1. Token blacklistWhen a user logs out, their JWT is stored here until it expires — prevents reuse of revoked tokens.
2. Permission cacheRBAC role/permission lookups are cached with a 300-second TTL — avoids a DB query on every request.
3. Rate limitingSliding-window counters per IP/user stored in Redis — enforces request limits without a DB.
4. Celery brokerTask messages from FastAPI are pushed onto Redis queues; Celery workers pull from them.
Key configREDIS_URL in .env
Key filesapp/core/redis.py · app/middleware/rate_limit.py · app/workers/celery_app.py

Celery 5.6

RoleDistributed task queue — offloads slow or scheduled work from the HTTP request/response cycle.
WhySending emails, generating PDFs, and pushing emergency notifications should never slow down an API response. Celery runs them in the background.
Queuesdefault — emails, PDFs, log cleanup
priority — emergency alerts (dedicated worker, never queued behind normal tasks)
BeatBuilt-in scheduler — runs cleanup_old_logs every Sunday 02:00 UTC automatically.
Windows noteMust use --pool=solo on Windows. Linux/prod uses the default prefork pool.
Key filesapp/workers/celery_app.py · app/workers/tasks.py

JWT Authentication (python-jose)

RoleStateless authentication — every protected request carries a signed JWT; the server validates the signature without hitting the DB.
WhyScalable across multiple API instances (no shared session store needed). Combined with Redis blacklisting for logout support.
Key configSECRET_KEY, ALGORITHM, ACCESS_TOKEN_EXPIRE_MINUTES in .env
Key filesapp/core/security.py · app/middleware/auth_middleware.py · app/core/dependencies.py

Role-Based Access Control (RBAC)

RoleFine-grained permission system — each endpoint requires a specific permission (e.g. blotter.create, system_logs.read). Permissions are assigned to roles, roles to users.
WhyA barangay system has multiple user types (admin, staff, resident, official) — RBAC lets you control exactly what each can see and do without hardcoding roles in every route.
CachePermission lookups cached in Redis for 300s — a heavy role with many permissions only hits the DB once per 5 minutes.
Key filesapp/modules/rbac/ · app/core/dependencies.py

Repository Pattern

RoleAll database queries are encapsulated in typed repository classes — routers never write raw SQL or ORM queries directly.
WhySeparates business logic from data access. Makes testing easy (swap the repo for a mock), and keeps routers thin and readable.
StructureBaseRepository[M] provides get, list, create, update, delete, bulk_create. Each module extends it with domain-specific queries.
Key filesapp/repositories/base.py · app/repositories/*_repository.py

Async DB Log Handler

RolePersists structured log records to the system_logs table without blocking HTTP requests.
HowUses an asyncio.Queue(maxsize=10,000) as a buffer. A background worker drains the queue in batches of 50 every 2 seconds — so even a burst of logs never slows down the API.
Context propagationContextVars automatically attach the current request_id and user_id to every log record — no need to pass them manually.
Key filesapp/core/log_handler.py · app/core/context.py · app/modules/system_logs/

Pytest + HTTPX

RoleAutomated test suite — 21 tests covering auth, CRUD endpoints, permissions, and middleware.
Whyhttpx.AsyncClient with ASGITransport lets tests hit the real FastAPI app in-process — no running server needed, no mocking the HTTP layer.
Run testspytest tests/ -v
Key filestests/ · pytest.ini
